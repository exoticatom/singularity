   eliminated.

**Net result:** A cleaner, mobile-friendly dashboard with a single reliable
online/offline indicator, a working full-page refresh button, and no template
error spam in the HA log.

## Part 1 — Firmware: RIMS PID / DC Mode Selector

**Commits:** `83499c4` (feature), `6bdc835` (build fix)
**Firmware:** v1.1.7 → v1.1.8
**Status:** ✅ Complete, built, deployed

### What shipped
- **`select.singularity_rims_mode`** — operator chooses **PID** or **DC** (direct
  duty) for the RIMS heater.
  - **PID mode:** heater duty is computed by the on-device PID loop against
    `number.singularity_pid_setpoint`.
  - **DC mode:** heater duty is driven directly by
    `number.singularity_rims_dc_power` (0–100%), bypassing the PID.
- PID is now always full-range **0–100%** (the old "PID Max Duty Cycle" limiter
  was removed — see dashboard v1.5.0).
- All 4 safety guards remain active in **both** modes (mode only chooses the duty
  *source*, never disables protection).

### Build fix (`6bdc835`)
- ESPHome **2026.8.1** broke the build on the new `select` platform.
- Fixed the same day; firmware builds clean on 2026.8.1.

## Part 2 — Dashboard UX Overhaul (v1.5.0 → v1.7.9)

**File:** `singularity_dashboard.yaml`
**Diff (v1.5.x → v1.7.9):** +242 / −94 lines
**Status:** ✅ All deployed via CI/CD

The dashboard header carries a full per-version changelog; this section groups the
~30 point releases into the themes that matter.

### 2.1 RIMS control card consolidation (v1.5.0 – v1.5.5)
- Added the PID/DC **mode selector** and **DC Power %** to both the main Brewing
  tab and the Settings tab (v1.5.0).
- Merged the two separate main-tab RIMS cards into a single **"RIMS Heater
  (SSR2)"** card (v1.5.3).
- Dropped Kp/Ki/Kd tuning rows from the main tab — tuning now lives only in
  Settings (v1.5.2); main tab shows **Target Temperature + DC Power** always,
  no mode-conditional hiding (v1.5.4).
- Moved the RIMS card up directly under the temperatures; the graph moved to the
  end of the column (v1.5.5).

### 2.2 Responsive Sections layout (v1.5.6 – v1.5.9)
- Converted the main tab to a **3-column** layout: `[Temps] [RIMS + Flows]
  [Graph]` (v1.5.6).
- Migrated **all tabs** from the old masonry to the **Sections view**
  (`type: sections`), giving auto-width, responsive columns that reflow on
  mobile (v1.5.7 – v1.5.8). Settings was split into three sections; flow cards
  moved into the temperature column.
- About tab section order swapped for readability (v1.5.9).

### 2.3 AN1 / AN2 flow cards redesign (v1.6.5 – v1.7.1)
Iterated the two flow sensors (AN1 · RIMS, AN2 · Sparge) into self-contained
`mushroom-template-card`s:
- Added **"AN1 · RIMS" / "AN2 · Sparge"** name headers (v1.6.7), then folded the
  names into each card's own secondary line and dropped the separate title cards
  (v1.7.0).
- Replaced the full-size **Reset** buttons with a compact reset **inside** each
  flow card, triggered by **hold_action** → `button.singularity_anX_reset_total`
  (v1.6.8 – v1.6.9).
- Secondary text shows Total/Flow, with **"hold to reset" on its own line**
  (`multiline_secondary: true`, v1.7.1).
- Icon color is rate-driven: idle = disabled/grey, low flow = red, normal = blue.

### 2.4 Connectivity indicator (v1.6.2 – v1.6.6, v1.7.9)
This was the trickiest thread — several dead ends, now resolved:
- **Dead end 1:** a `custom:button-card` header indicator → **config error**
  (button-card is **not** installed as a HACS resource). Reverted (v1.6.2 –
  v1.6.3).
- **Dead end 2:** the badge/banners pointed at
  `binary_sensor.singularity_esp32_fast_status` — an entity that **never
  existed** (it was a *planned* HA template helper, never created). This threw
  "Entity not found" and had silently hidden the banners all along. Fixed by
  pointing everything at the real ESPHome sensor
  **`binary_sensor.singularity_esp32_status`** (v1.6.4).
- **Dead end 3:** a native entity badge **ignores** a templated `color` (renders
  grey). Fixed with **two visibility-gated badges** — a static-green one shown
  when `on`, a static-red one shown when `off` (v1.6.6).
- **Final form (v1.7.9):** removed the redundant big "singularity.local —
  Online/Offline" banner. The **tab-bar badge** (green/red dot + "singularity")
  is now the single indicator — and it appears on **every** tab, not just the
  main one.

> **HA constraint learned:** Lovelace cannot place a card in the actual tab/header
> bar. View-level `badges:` render in a strip **directly under** the tabs — that
> strip is the closest achievable "top" indicator.

### 2.5 Page-refresh control (v1.7.2, v1.7.5 – v1.7.8)
- First shipped as a native **soft refresh** chip (`action: navigate` to the same
  view — re-renders, no HACS, but not a true reload) (v1.7.2).
- Replaced with a **browser_mod** chip calling `browser_mod.refresh` for a **true
  full browser reload** (v1.7.5). **Requires the browser_mod HACS integration**
  (confirmed installed and working).
- Position iterated per request: under flows → top-right → bottom → **final: last
  card inside Column 3, directly under the temperature graph** (v1.7.6 – v1.7.8).

### 2.6 Reliability fixes (v1.7.3 – v1.7.4)
- **Activity Log card** made full-width and taller (`grid_options rows: 16`),
  window extended to **48h** (v1.7.3).
- **Template error fix (v1.7.4):** the 4 temperature cards used
  `{{ states(entity) | round(1) }} °C` with **no default**, which threw
  `ValueError: could not convert string to float: 'unknown'` whenever a sensor
  was `unknown`/`unavailable` (i.e. ESP32 offline) — flooding the HA log. Now
  guarded with `float(none)` → shows **"N/A"** instead of erroring.
